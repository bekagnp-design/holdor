# HOLDOR — notes for Claude Code

**HOLDOR** — a Game of Thrones–themed **action RPG** in one HTML file, played as a Telegram Mini App
(`t.me/HoldorTDBot/play`, opens `https://bekagnp-design.github.io/holdor/?v=N`). GitHub Pages serves this repo's root.
Since 2026-11-22 (v2.0.0) the game is an open-world action RPG on a 3D Westeros built from the game's own map art: the
player **is one of his unlocked champions** (one hero, no companions), real-time combat, levels / gear / quests,
**permadeath** (the hero's gold, gems, gear and level die with him; the account keeps world progress, titles, the Hall of
the Fallen), other players visible on the map, a zone chat. The tower defense of v1.0.x–v1.5.1 is an archive (see State).
Owner: MR B. Talk to him in **Georgian**, direct and analytical, no praise or filler.
**The architecture contract is `src/rpg/ARCH.md`** (one global `R`, events, the save shape, coordinates, controls, file
ownership; its Addendum 2 overrides the older text). Read it before touching `src/rpg/`. The design: `docs/rpg-design.md`.

## Build, test, release
```
python3 src/build_rpg.py                  # → beta/index.html
node tests/rpg/run_rpg.js                 # every suite; every line must say OK
CHROMIUM_PATH=/opt/pw-browsers/chromium-1243/chrome-linux64/chrome node tests/rpg/t_smoke.js   # one suite
```
- Tests need Playwright: `npm i`, then `npx playwright install chromium`; if the network blocks that download, set
  `CHROMIUM_PATH` to any installed Chromium/Chrome. Headless Chromium renders the WebGL terrain with its software renderer.
- The game runs **60 fixed steps per game second** (`R.step()`); tests call it directly and seed `R.rng(seed)` for
  deterministic runs. The whole game object `window.R` is public — keep it that way. Keyboard: WASD/arrows, J attack,
  K dodge, 1-2-3 skills, R potion, F interact, Q/E rotate the camera, M map, I bag, Esc menu. Entities keep 2D ground coordinates; the renderer reads the terrain height.
- The red `#err` overlay must stay hidden in every test; a console error fails the suite.
- A new version: bump `R.VERSION` in `src/rpg/js/00_core.js`, change only the modules you own (+ their CSS and test),
  build, run the suite, update `docs/build-backlog.md` (one section) and `docs/roadmap.md`.
- One version = one PR that touches only `src/rpg/`, `tests/rpg/`, `backend/`, `docs/`, `beta/` — never the root
  `index.html`. MR B merges it, Pages serves `https://bekagnp-design.github.io/holdor/beta/` a minute or two later, he
  tests it on his phone (checklist in `docs/todo-mr-b.md`).
- Release: after every version whose tests pass, apply its Supabase file first (named migration + a `holdor_backup`
  copy, function hashes checked against the file), then a separate PR `vX.Y.Z` that copies `beta/index.html` →
  `index.html` and nothing else, and merge it. **Since 2026-11-22 MR B tests every build in Telegram itself** ("დააბდეითე
  ტელეგრამიც, ყოველ ჯერზე ტელეგრამში დავტესტავ"): every integrated build goes to the beta PR *and* right after it to a
  release PR (`release/v2.0.0-tN` → root `index.html`), both merged. Never put an untested build in the root. `?v=N` in the Telegram mini-app
  URL is set by MR B in BotFather (bump it if Telegram shows an old build). The Edge Function `stars` update and the cron
  files v28–v30 still wait for "გაუშვი ბოტი".

## Rules from MR B (do not break)
- Never ask for, paste, echo or commit the Telegram bot token. It lives only in Supabase `app_secrets` (the Edge Function
  `stars` reads it there per request). The client carries only the Supabase URL and the publishable key.
- Every statistic shown to players is real server data or the player's own save — nothing invented, no fake player counts.
- Manual steps he must do (Supabase SQL, checks) come **one at a time**, each verified before the next. SQL first, then
  the client that needs it.
- End every reply with the next step, one development idea, and a short **Roadmap** block (the current version and the
  next ones from `docs/roadmap.md`, what each changes). Plan versions ahead and keep that table current.
- Sword Art Online and Kingdom Rush are mechanics references only: no copied names, art, maps, effects, music, text.
  Game of Thrones places and houses are the theme; write original lines, never quotes from the books or the show.
- UI: one dominant primary button per screen, everything readable in one glance, ≥ 44 px targets, no walls of text,
  English UI text, dark fantasy palette with the house colour as the accent (`R.data.houses[h].col`).
- Permadeath is the owner's decision: no revive, no gold-loss respawn, no Stars for power (v2.3 sells cosmetics only).
- Public boards and the chat never show Telegram ids (`mine` marks the player's own row). Server identity is `tg_id`
  (+ `seat` where the SQL keeps it); the old seats rule (I/II/III, `tg_id + seat`) stays for the archived TD data.
